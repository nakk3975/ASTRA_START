# 운영

## 프로세스와 데이터베이스

Node 24.22.1 이상 25 미만, 외부 PostgreSQL, 단일 Node 인스턴스로 시작한다. 서버는 HTTP/WS를 같은 포트로 서비스한다. 프록시는 WebSocket Upgrade와 HTTPS를 전달해야 한다. PUBLIC_ORIGIN은 사용자가 접속하는 HTTPS 원점이며 경로와 마지막 슬래시를 붙이지 않는다. SESSION_SECRET과 DATABASE_URL은 서버 환경 변수에만 둔다.

자동 마이그레이션은 CREATE TABLE IF NOT EXISTS 방식의 최초 스키마다. 기존 테이블을 삭제하지 않는다. 실제 운영 업그레이드에는 별도 버전 마이그레이션을 추가해야 한다.

## 데이터의 확정

1. 게스트/방 멤버 인증 및 일회용 join ticket을 확인한다.
2. 방 actor의 직렬 큐에서 입력을 검증하고 복사본에 적용한다.
3. 트랜잭션에서 writer lease/epoch와 이전 durable version/hash를 확인한다.
4. 변경분, 멱등성 영수증, 방 head와 소유권 변경을 한 COMMIT으로 확정한다.
5. COMMIT 이후에만 경제 상태 patch와 ACK를 내보낸다.

50ms 논리 tick, batch당 최대 5tick, 정상 시간 부채를 따라잡되 긴 정지를 무제한 catch-up하지 않는다. 영구 상태는 tick마다 변경분으로 저장하며 전체 스냅샷은 30초 간격이다. 저장 지연/실패 시 pending으로 표시하고 확정 상태를 다시 읽는다. COMMIT 결과가 불명확하면 다른 DB 연결에서 방 행 잠금을 얻은 뒤 commit_id 존재 여부를 확인한다.

서버 종료 시 입력을 멈추고 확정 스냅샷을 저장한다. 모든 연결이 없으면 경제 시간은 멈춘다. 빈 방은 채널 보존 시간 이후 메모리에서 해제한다. 재시작 시 오프라인 생산을 계산하지 않는다. 수동 일시정지는 재접속해도 유지된다.

## 백업과 복구

외부 PostgreSQL 제공자의 백업/PITR을 활성화하거나 `pg_dump`로 별도 보관한다. 복구 키는 방 소유권 확인 수단이며 DB 백업을 대체하지 않는다. 해시가 틀린 최신 스냅샷은 이전 스냅샷과 연속 delta로 복구한다. 유효한 사슬이 없으면 SAVE_CORRUPT로 중단하며 빈 월드로 덮지 않는다. 콘텐츠 버전/경제 해시 불일치는 CONTENT_VERSION_MISMATCH로 중단한다. 이 버전에는 자동 데이터 마이그레이션을 포함하지 않는다.

## 한도와 비용

초기 최대 동시 메모리 방 3개, 방당 6명, 입력/명령/상태 조회 rate limit, 큐 한도, 메시지 8KiB 제한을 runtime_v1.json에서 읽는다. 송신 버퍼가 hard limit에 이르거나 soft limit 이상이 지속되면 해당 클라이언트를 끊어 전체 상태 재동기화를 요구한다. 느린 클라이언트 시험 및 3방 동시 부하 시험은 QA 보고서의 실제 실행 상태를 확인한다.

Render Free 예시가 포함되어 있지만 배포하지 않았다. 무료 서비스의 슬립/재시작은 긴 접속 대기를 만들 수 있으므로 운영 품질과 용량은 실제 선택한 요금제에서 측정해야 한다. Render 로컬 파일에 운영 DB를 두지 않는다. PostgreSQL 연결 비용과 저장량은 공급자 사용량을 확인한다.

## 상태 확인

- `GET /health/live`: 프로세스 HTTP 생존.
- `GET /health/ready`: 종료 중이 아니고 DB SELECT 1이 성공함. 모든 방의 무결성 상태를 의미하지 않는다.
- 게임 설정의 ‘저장 확인’: SAVE_BARRIER 영수증의 durable version을 표시.
- 로그: ACTOR_FAILURE에 실제 서버 오류가 출력된다. 개발 환경에서만 `.local/diagnostics.log`에도 기록된다. 게스트 비밀/복구 키는 로그에 쓰지 않는다.

키를 잃었을 때는 새 게스트로 로그인 후 홈의 ‘복구 키로 내 작업장 찾기’에서 작업장 ID와 키를 입력한다. 회수된 키는 즉시 교체되므로 새 키를 보관한다. 일반 초대 코드로 소유권을 복구할 수 없다.
