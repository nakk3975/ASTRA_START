# 3.4.0 — 화면 복구·재료 자동 가공·운반 동작

## 철판 설치와 재시작

설치 수가 바뀔 때 `rocket.traverse(node => node.userData.release?.())`를 실행했다. `Visual.release`는 자신의 root를 부모에서 떼므로 순회 중 children 배열이 변경되었다. Three.js의 순회가 원래 길이로 계속되어 `Cannot read properties of undefined (reading 'traverse')`가 발생했다. 같은 코드가 CarryView.dispose에도 있어 재시작의 React effect cleanup까지 실패할 수 있었다. 사용자 이미지의 오류 상세는 접혀 있었으므로 그 화면의 실제 메시지를 읽은 것은 아니다. 코드에서 동일한 설치/정리 경로의 예외를 재현했다.

`releaseTree`는 먼저 콜백을 모으고 순회를 마친 뒤 실행한다. 콜백과 Visual/CarryView 정리는 멱등이다. 삭제된 View의 비동기 모델 로딩 실패가 새 화면을 덮지 않게 했다. 로켓 설치 때에는 기존 모델의 완성도·불투명도만 갱신하고, LOD가 바뀔 때만 모델을 교체한다. 출력 게이지도 존재하는 출력 아이템으로 계산한다.

## 재료 자동 가공

- 첫 재료를 금색 받침대에 E로 넣으면 제작 항목을 선택한다. 초반 철광석1 → 철 주괴1 → 철판1. 주괴를 다시 투입하면 철판 가공이다.
- 같은 재료에 후보가 여러 개면 현재 미완성 로켓 단계와 실제 재고·진행 중 작업을 기준으로 부족한 부품을 우선한다. 예: 엔진 단계에서 필요한 철판이 준비되어 있으면 주괴를 기어로 가공한다. 투입 전에 화면에 결과를 표시한다.
- 조합 작업의 재료가 남아 있으면 해당 제작 항목을 유지한다. 추가 재료 종류·수량을 표시하고, 잘못된 재료는 손에 남긴다. 입력대에서 대기 재료를 꺼내면 다시 다른 재료를 가공할 수 있다.
- 기본 공방 작업대는 로켓 부품을 자동화 상자로 바꾸지 않는다. 별도 자동화 workbench는 적게 보유한 설비 상자를 우선한다. 특정 상자의 직접 구매도 유지한다. 이전 버전의 부분 투입 작업은 그대로 마칠 수 있다.
- 수동 레시피 드롭다운과 주괴/철판 선택 버튼을 제거했다. 예전 클라이언트의 RECIPE 명령은 호환되지만 새 투입은 자동 선택을 적용한다.

## 캐릭터와 연결

실제 표시 이동 거리에 맞춰 보폭을 진행하고, 정지 시 다리를 중립으로 되돌린다. 두 팔의 상완·전완을 계산하여 손을 앞쪽 받침 위치에 모으고 운반물은 양손 중간에 붙인다. 몸의 방향에 따라 함께 회전하며 내려놓은 물건의 크기를 복원한다. 다리 길이 변화에 맞춰 골반 높이를 보정한다. 4종 캐릭터와 두 LOD에 동일하게 적용하며 유료 모델 생성/원본 GLB 수정은 없다.

HTTP 세션/인증 거부는 80ms 반복 요청을 멈추고 재연결 버튼을 제공한다. 일시 통신 실패는 1~15초 간격으로 재시도하고 개별 요청은 15초로 제한한다. 서버의 저장 상태를 초기화하지 않는다.
