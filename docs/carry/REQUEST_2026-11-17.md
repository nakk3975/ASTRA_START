기존 「고철에서 우주까지 / From Scrap to Space」 프로젝트를 아래 요구사항에 맞게 수정해 주세요.

당신은 게임 UI/UX, 실시간 3D 웹 렌더링, 협동 게임플레이를 함께 담당하는 개발자입니다.

설명이나 화면 시안 작성에 그치지 말고, 기존 프로젝트의 코드와 에셋을 확인한 뒤 실제 실행 가능한 게임으로 구현하고 검증해 주세요.

이 요청에서 명시한 새 규칙은 이전 기획의 충돌하는 규칙보다 우선합니다.
충돌하지 않는 기존 콘텐츠와 정상 작동하는 기능은 활용하세요.
근거 없이 프로젝트를 새로 만들거나 기존 저장 데이터를 삭제하지 마세요.


1. 가장 중요한 목표

게임은 1~6인 온라인 협동으로 플레이합니다.
혼자서도 진행할 수 있어야 합니다.

핵심 플레이는 다음과 같습니다.

바닥의 실제 고철 오브젝트를 한 개 집는다.
→ 손에 들고 가공 기계까지 이동한다.
→ 입력 받침대에 고철을 넣는다.
→ 기계가 가공한 실제 부품이 출력 트레이에 나온다.
→ 그 부품을 다시 집어 발사대까지 운반한다.
→ 해당 소켓에 직접 설치한다.
→ 후반에는 컨베이어와 크레인으로 같은 운반 과정을 자동화한다.

자원이 자동으로 숫자 창고에 들어가는 방식으로 구현하지 마세요.
HUD의 숫자는 실제 물건과 조립 상태를 요약하는 용도로 사용할 수 있습니다.

게임 월드는 실제 WebGL 3D 공간이어야 합니다.
바닥, 구조물, 캐릭터, 고철, 부품, 기계, 로켓을 실제 3D 메시로 렌더링하세요.

CSS와 SVG는 HUD, 아이콘, 미니맵에 사용하세요.
CSS transform으로 기울인 판이나 SVG 작업장 그림을 실제 3D 맵 대신 사용하지 마세요.


2. 참고작과 카메라 방향

「How They Built the Pyramids」에서는 다음을 참고합니다.

- 입체적인 작업 현장
- 손으로 물건을 옮기는 과정
- 물건이 쌓이고 이동하는 모습
- 생산 과정이 점점 자동화되는 변화

「Overcooked」에서는 다음을 참고합니다.

- 동료의 행동이 쉽게 읽히는 화면
- 여러 사람이 오가며 역할을 나누는 동선
- 유쾌한 캐릭터와 즉각적인 행동 피드백

참고작의 모델, 로고, UI를 그대로 복제하지 마세요.

이번 프로젝트는 참고작의 1인칭 카메라를 그대로 재현하는 요청이 아닙니다.
기본 카메라는 고정 각도의 3인칭 쿼터뷰입니다.

카메라 초기값:

- 원근 카메라
- 수직 FOV 35도
- 지면 기준 내려다보는 고도각 45도
- 수평 방위각 45도
- 작업자 키 약 1.8m 기준, 목표점까지 거리 약 32m에서 시작

이 값은 튜닝 출발점입니다.
기존 정사영 카메라의 거리 값을 그대로 재사용하지 마세요.

FHD 기본 화면에서 작업자의 발부터 머리까지 약 56~80 CSS px로 보이고,
손에 든 고철과 철판을 구분할 수 있도록 거리와 구도를 조정하세요.

카메라는 플레이어의 지면 이동을 데드존 방식으로 따라갑니다.
중앙 약 30% × 28% 안에서 움직일 때는 불필요하게 카메라를 움직이지 마세요.

자동 회전, 자동 줌, 머리 흔들림, 착지 진동, 달리기 FOV 변화,
모션 블러는 기본적으로 사용하지 마세요.

램프를 오를 때 카메라 높이는 완만하게 따라가되,
카메라와 목표점에 같은 높이 변화를 적용해 고정 각도를 유지하세요.

C 키로 재중앙 정렬을 제공합니다.
현재 작업 구역에 카메라를 고정하는 옵션도 제공하세요.

초기 화면에서 폐기장→가공장→발사대의 방향이 읽혀야 합니다.
맵 전체를 항상 한 화면에 넣느라 캐릭터와 물건을 지나치게 작게 만들지 마세요.

높은 구조물이 캐릭터를 가리면 배치 조정, 부분 투명화,
캐릭터 표시 등으로 시야를 확보하세요.


3. 비주얼과 실제 3D 맵

스타일은 밝고 유쾌한 ‘협동 공돌이 작업장’입니다.
과장된 형태와 무광 재질을 사용하는 스타일라이즈드 3D로 만드세요.

색상 기준:

- 바닥 기본 계열: #23272F
- HUD: #161920, 불투명도 약 85%
- 주요 행동과 안전선: #F59E0B
- 조립 완료와 정상 연결: #06B6D4
- 팀원: 구별되는 6가지 색 + 번호 또는 문양

바닥 전체를 같은 어두운 색으로 칠하지 마세요.
밝기가 다른 콘크리트, 철판, 경계 턱, 램프로 구역을 구분하세요.

따뜻한 주광과 부드러운 보조광, 바닥 접촉 그림자를 사용해
물체의 높이와 무게를 보여 주세요.

청사진 그리드는 평소에는 희미하게,
설비 배치 모드에서는 해당 구역에만 명확하게 표시하세요.

맵은 하나의 이어진 작업 공간입니다.

왼쪽: 고철 폐기장
- 낮은 철제 울타리
- 고철 더미와 수거함
- 바닥에 놓인 집을 수 있는 개별 고철

중앙: 프레스·용접 작업장
- 입체적인 기계와 작업대
- 눈에 보이는 입력 받침대
- 완성품이 놓이는 출력 트레이
- 기계 앞에서 작업할 수 있는 접근 공간

오른쪽: 우주선 발사대
- 두께가 있는 기초 플랫폼
- 실제로 오를 수 있는 완만한 램프
- 로켓 골조
- 부품을 설치하는 실제 소켓

기계 사이에는 컨베이어와 크레인을 설치할 여유 공간을 확보하세요.
컨테이너, 파이프, 전선, 표지판 등의 장식은 주요 통로를 가리지 않게 배치하세요.

바닥과 구조물의 옆면, 높이 차이, 그림자가 보여야 합니다.
올라갈 수 있는 플랫폼은 캐릭터와 아이템의 Y좌표·충돌·서버 판정도
실제 높이를 반영해야 합니다.

기존 서버가 XZ 평면만 처리한다면 해당 부분도 확장하세요.

주 통로는 최소 캐릭터 3명이 나란히 지날 정도의 폭을 확보하고,
가공장과 발사대 주변에 우회 동선을 만드세요.

플레이어끼리는 통과 가능한 아케이드 충돌 규칙을 기본으로 사용해
몸으로 출입구를 막아 진행을 중단시키는 상황을 방지하세요.
벽, 기계, 지형 충돌은 유지합니다.


4. Meshy 에셋 사용

기존 Meshy 모델과 프로젝트의 GLB 에셋을 먼저 확인하고 재사용하세요.
필요한 에셋만 모듈 단위로 추가하세요.
맵 전체를 하나의 거대한 Meshy 모델로 생성하지 마세요.

- 바닥·램프·안전선·단순 구조물:
  정규화된 3D 지오메트리 또는 반복 가능한 모듈 사용

- 캐릭터·특징 있는 고철·부품·기계·크레인·로켓:
  Meshy 에셋 우선 활용

월드 단위는 1단위=1m, Y축 위쪽으로 통일하세요.
피벗, 회전, 크기, 재질, 그림자를 정리하세요.

운반물에는 잡는 위치,
기계에는 입출력 위치,
로켓에는 설치 소켓을 별도로 정의하세요.

시각 메시와 충돌체를 분리하세요.
복잡한 메시 전체를 동적 충돌체로 사용하지 마세요.

캐릭터에는 대기, 걷기, 들기, 운반, 내려놓기, 작업 동작을 연결하세요.
운반 중에는 실제 부품이 손 또는 가슴 앞의 일관된 위치에 보여야 합니다.

고철, 철판, 탱크는 실루엣부터 구별되어야 합니다.
모든 물건을 같은 상자에 아이콘만 바꾸어 표현하지 마세요.
설비 설치용 상자는 별도 아이템으로 사용할 수 있습니다.

에셋 목록에는 경로, 실제 삼각형 수, 재질 수, 텍스처 크기,
피벗, 충돌체, 소켓, 애니메이션 상태를 기록하세요.

외부 이미지 핫링크에 의존하지 마세요.
프로젝트 내부의 GLB와 텍스처는 허용합니다.
HUD 아이콘에는 인라인 SVG를 사용할 수 있습니다.

모델이 준비되지 않은 동안에는 식별 가능한 3D 임시 메시로 기능을 개발하세요.
최종 결과에 임시 모델이 남았다면 정확히 표시하세요.

신규 유료 생성은 기존에 허용된 범위와 예산 안에서 수행하세요.
이 요청을 무제한 재생성 허가로 해석하지 마세요.


5. 직접 집기·운반·가공·조립

플레이어는 한 번에 실제 오브젝트 한 개를 운반합니다.
기존의 숫자 인벤토리, 4슬롯, 묶음 운반이 있다면
핵심 자원 운반을 단일 손 슬롯으로 변경하세요.

빈손으로 가까운 물건에 접근해 E를 누르면 집습니다.
이미 물건을 들고 있다면 추가로 집을 수 없습니다.

상호작용은 가까운 유효한 대상에서만 허용하세요.
벽 너머 집기와 먼 물건을 클릭해 즉시 수집하는 행동은 허용하지 마세요.

대상에는 얇은 윤곽선과 상황별 안내를 표시하세요.

예:
E 고철 들기
E 프레스에 넣기
E 철판 꺼내기
E 엔진 부품 설치

무거운 고철을 들면 기본 이동속도의 80%로 이동합니다.
HUD에 이동속도 -20%를 표시하세요.
감속 여부는 아이템 정의에서 관리하세요.

Space:
앞쪽의 유효한 바닥에 내려놓기.
바닥이나 기계 내부에 끼지 않게 위치를 검증하세요.

F:
바라보는 방향에 짧게 던지기.
공중 이동과 바닥 충돌을 표현하고,
최대 속도·거리와 벽 관통을 제어하세요.

캐릭터와 손의 물건은 안정적으로 제어하고,
떨어뜨리거나 던진 물건에 중력·충돌을 적용하세요.
모든 캐릭터를 래그돌로 만들 필요는 없습니다.

가공:

- 손의 재료를 유효한 입력 받침대에 투입합니다.
- 여러 재료가 필요하면 실제 물건을 한 개씩 공급합니다.
- 대기 재료와 입력 슬롯이 공간 안에 보여야 합니다.
- 재료가 모이면 가공이 시작됩니다.
- 가공 완료 후 실제 부품이 출력 트레이에 나타납니다.
- 출력물이 즉시 개인 인벤토리나 공유 창고로 이동하면 안 됩니다.
- 출력 트레이가 가득 차면 대기합니다.
- 결과물을 무한 생성하거나 조용히 삭제하지 마세요.

던진 물건이 기계 외벽에 닿았다는 이유만으로
투입·가공·설치가 완료되면 안 됩니다.

조립:

- 완성 부품을 직접 들고 유효한 설치 소켓에 접근해야 합니다.
- 현재 단계에 맞는 부품만 설치할 수 있습니다.
- 설치 전 반투명 부품 미리보기와 필요한 부품 이름을 표시합니다.
- E로 설치하면 손의 부품이 소비됩니다.
- 실제 로켓 메시와 준비도를 함께 갱신합니다.
- 틀린 부품, 이미 채운 소켓, 빈손 상태에서는
  진행도를 올리지 않고 이유를 표시합니다.


6. 실물 상태와 실제 협동

각 물건에는 서버가 발급한 고유 itemId가 있어야 합니다.
물리 엔진의 임시 body handle을 저장용 아이템 ID로 사용하지 마세요.

물건은 다음 중 정확히 한 상태에만 속합니다.

- 바닥 또는 공중
- 특정 플레이어의 손
- 기계의 입력·가공·출력
- 컨베이어·크레인·대기 트레이
- 설치 완료 또는 소비

서로 다른 상태에 복사본이 동시에 남으면 안 됩니다.

제작에서는 입력을 한 번 소비하고,
새 출력 아이템 ID를 한 번만 생성하세요.

집기, 내려놓기, 던지기, 투입, 제작 완료, 설치,
자동화 인계는 서버가 검증하고 한 번만 반영합니다.

상태 변경 명령에는 고유 명령 ID를 부여하세요.
같은 명령이 재전송되어도 추가 소비·생성을 하지 않아야 합니다.

두 명이 같은 고철을 동시에 집으면 한 명만 성공해야 합니다.

클라이언트는 입력을 전달하고,
서버는 이동·소유권·가공·조립과 자유 물체의 최종 상태를 판정합니다.
위치 예측과 보간은 화면을 부드럽게 만드는 용도로 사용하세요.

기존 실시간 연결 구조가 있다면 활용하세요.
동료 카드와 자동 이동 캐릭터를 추가하는 것만으로
멀티플레이를 구현했다고 보고하지 마세요.

실제 방 코드와 실제 접속자 정보를 사용하세요.
테스트 봇은 봇이라고 표시하세요.

접속 종료 시 운반물은 서버 규칙에 따라
해당 위치 근처의 안전한 바닥에 한 번만 반환합니다.

낙하하거나 맵을 벗어난 물건에는 추적 가능한 복구 규칙을 적용하세요.
물건이 조용히 사라지거나 숫자 창고로 바뀌면 안 됩니다.

저장·불러오기와 서버 재시작에서도 소유권과 가공 상태를 유지하세요.
검증된 마이그레이션이 없다면 기존 저장본을 보존하고
새 규칙 버전의 새 게임을 생성하세요.


7. 컨베이어와 크레인 자동화

자동화는 같은 itemId의 실물을 월드 안에서 운반해야 합니다.
보이지 않는 자원 이동과 장식 애니메이션으로 대체하지 마세요.

직선·코너 컨베이어:
방향에 따라 다음 구간 또는 기계 입력 포트로 물건을 전달합니다.
다음 구간이 막히면 대기하고, 물건이 겹쳐 무한 적재되지 않게 하세요.

크레인:
지정된 공급 위치에서 한 물건을 들어
지정된 수령 위치로 옮기는 왕복 방식으로 시작하세요.

목적지는 출발 시 예약하거나 도착 시 다시 검증하세요.
도중에 목적지가 막히면 물건을 유지한 채 대기하세요.
수령 성공 전에는 인계 완료로 처리하지 마세요.

크레인 운반 중에는 수동 집기를 막고,
트레이에 내려놓은 뒤 집을 수 있게 하세요.

퀵슬롯:
1 직선 컨베이어
2 코너 컨베이어
3 크레인
4 대기 트레이

퀵슬롯은 설계도를 선택하는 기능입니다.
설비 상자를 작업대에서 실물로 제작하고 직접 운반해 설치하세요.

손의 설비 상자 종류와 선택한 청사진이 일치할 때만 설치합니다.
서버가 위치·접근·충돌을 확인한 뒤
상자 1개 소비와 설비 생성을 한 번에 처리하세요.

설치 실패·취소에는 상자를 소비하지 마세요.
제작 때 지불한 재료를 설치 시 다시 차감하지 마세요.

배치 미리보기, 설치 가능 여부, R 회전, Esc 취소를 제공합니다.
E 또는 월드 좌클릭으로 설치를 확정합니다.

키보드 배치는 캐릭터 앞의 유효한 칸을 대상으로 하세요.
마우스 배치도 가까운 설치 가능 범위 안에서만 허용하세요.

벽·출입구·발사 소켓을 막는 배치는 거부하고 이유를 표시하세요.


8. 운반 방식에 맞는 밸런스

한 개씩 운반하는 방식에 예전 묶음 운반 밸런스를 그대로 적용하지 마세요.

기존 자원 종류, 레시피 관계, 건설 단계 중 활용 가능한 부분은 유지하되
수량과 시간은 다시 계산하세요.

먼저 개발용 검증 환경에서 작은 루프를 완성하세요.

검증용 예:
고철 1개 → 철판 1개
가공 4초
시험 설치 목표 철판 4개

이 검증 수치를 본편 전체 밸런스와 혼합하지 마세요.

본편의 초기 목표:
- 초보 1인의 첫 설치: 약 60~120초
- 첫 유용한 자동화: 약 5~10분

이는 초기 설계 목표입니다.
실제 플레이 측정 전에는 달성했다고 보고하지 마세요.

계산에는 다음을 포함하세요.

- 빈손 이동 시간
- 운반 이동 시간
- 집기·투입·설치 시간
- 다른 작업과 겹치지 않는 가공 대기 시간
- 기계의 처리량과 입출력 정체

동시에 진행 가능한 가공 시간을 중복해서 더하지 마세요.

1·2·4·6인에서 왕복 횟수, 생산 병목, 작업대 점유,
설치 작업량을 확인하세요.

인원수만큼 목표량을 단순 곱하지 마세요.
6명이 하나의 입력구에서 기다리게 만들지 마세요.

진행 중 입퇴장으로 이미 납품한 재료나 현재 목표량이
갑자기 바뀌지 않게 하세요.
방의 난이도 기준 인원과 중도 입퇴장 정책을 명시하세요.

원료 보충용 바닥 아이템 한도와 가공 출력 공간을 구분하세요.
원료가 모든 공간을 차지해 가공 결과를 생성하지 못하면 안 됩니다.

출력 공간을 예약하거나,
완료 대기 후 공간이 비면 확실히 재개하도록 처리하세요.

자원 소진이나 오브젝트 한도로 진행이 영구 정지하지 않게 하세요.
수거함의 제한된 보충 규칙과 가득 찼을 때의 대기 규칙을 정하세요.

자동화 설비를 제작하는 데 그 설비 자체가 먼저 필요한
순환 선행조건도 없어야 합니다.

밸런스 수치는 별도 설정으로 관리하고
기존 값·새 값·변경 이유·검증 여부를 기록하세요.


9. HUD

평상시 실제로 보이는 HUD 패널 영역의 합집합은
전체 화면의 25% 이내를 목표로 합니다.

중앙 이동·운반·설치 동선을 넓게 남기세요.
사용자가 직접 연 설정·도움말 모달은 이 비율에서 제외합니다.

좌측 상단:

- 실제 접속자 최대 6명의 작은 카드
- 이름, 색·번호, 현재 들고 있는 물건 또는 작업 상태
- 실제 방 코드와 복사 버튼
- 복사 성공·실패 피드백

중앙 상단:

- 현재 조립 단계
- 지금 필요한 부품과 실제 납품 수량
- 전체 발사 준비도
- 경과 시간

기존에 명시된 제한 시간 모드가 없다면
임의의 카운트다운 실패 조건을 추가하지 마세요.

단계 이름과 2/4 같은 수치를 하드코딩하지 마세요.
실제 게임 데이터에서 읽어 표시하세요.

우측 상단:

- 실제 좌표와 일치하는 미니맵
- 폐기장, 기계, 발사대, 동료, 핑
- 핑, 음향 토글, 도움말, 설정

음성 채팅을 구현하지 않았다면 마이크 버튼은 제외하세요.
음성 채팅은 이번 필수 범위가 아닙니다.

하단 중앙:

- HAND SLOT 하나
- 빈손 또는 현재 들고 있는 물건
- 필요하면 무게·이동속도 영향
- 상황에 맞는 E/Space/F 안내
- 자동화 퀵슬롯 1~4

월드 위에는 현재 대상과 필요한 소수의 진행 표시만 띄우세요.
모든 물건에 이름표와 큰 게이지를 표시하지 마세요.

HUD의 빈 영역은 게임 입력을 막지 않게 하고,
실제 버튼만 포인터 이벤트를 받도록 하세요.


10. 입력

WASD: 화면 기준 이동
E: 상황별 상호작용 / 배치 모드에서 설치 확정
Space: 내려놓기
F: 짧게 던지기
1~4: 자동화 설계도 선택
R: 배치 회전
C: 카메라 재중앙 정렬
G: 핑 모드
Esc: 현재 모드·창 취소, 활성 모드가 없으면 메뉴
? 또는 도움말 버튼: 조작 설명

기존 F 키가 카메라 복귀였다면 C로 변경하고
HUD, 도움말, 실제 입력 처리를 모두 일치시키세요.

배치·핑 모드는 동시에 하나만 활성화합니다.

입력 우선순위:
입력창·모달 → 현재 배치·핑 모드 → 일반 플레이

같은 E 입력으로 설치와 주변 물건 집기가 동시에 실행되면 안 됩니다.

한글 입력 환경을 고려해 게임 키는 event.code 기준으로 처리하세요.
입력창·채팅에 포커스가 있으면 이동과 월드 행동을 차단하세요.

포커스 상실·탭 전환 시 눌린 키 상태를 해제하세요.
모드를 닫을 때 누르고 있던 행동 키를 재실행하지 마세요.
E·F·Space는 키 반복으로 여러 번 처리되지 않게 하세요.

게임 입력이 활성화된 때에만 Space 등의 브라우저 기본 동작을 차단하세요.
게임 화면을 클릭한 뒤 실제 이동이 되는지 확인하세요.


11. 해상도·성능·실행 안정성

게임 루트와 캔버스는 뷰포트를 채우고 문서 스크롤이 없어야 합니다.
100dvh와 필요한 100vh 대체 처리를 적용하세요.
HUD는 캔버스 위에 오버레이합니다.

각각 확인할 CSS 뷰포트:

- 1920×1080
- 2560×1440
- 3840×2160
- 3440×1440
- 5120×1440
- 1366×768 축약 레이아웃

4K와 울트라와이드를 같은 조건으로 취급하지 마세요.

UI 스케일은 clamp()와 뷰포트 가로·세로를 함께 고려하세요.
가로 vw만으로 확대하지 마세요.

초기 스케일 기준:
clamp(0.85, min(W/1920, H/1080), 1.6)

W/H는 CSS 픽셀 기준입니다.
사용자가 UI 크기를 조절할 수 있게 하세요.

최종 표시 크기에서:
- 핵심 상태·행동 안내 최소 14 CSS px
- 주요 버튼 클릭 영역 최소 44×44 CSS px

작은 화면에서는 글자와 버튼을 계속 줄이지 말고
카드 재배치, 설명 접기, 보조 정보 축약으로 공간을 확보하세요.

기존의 적합한 3D 렌더러를 활용하세요.
필요하면 Three.js와 Rapier 같은 도구를 사용하되,
정상 작동하는 기존 구조를 이유 없이 교체하지 마세요.

렌더링, 시뮬레이션, 네트워크, HUD 갱신을 분리하세요.
프레임마다 전체 월드 상태를 UI 컴포넌트 상태로 복사하지 마세요.

반복 메시 인스턴싱, 단순 충돌체, 정지 물체 수면 처리,
적정 텍스처 크기, 그림자 거리, 렌더 해상도 제한을 적용하세요.

렌더링·활성 물리 바디 한도를
중요한 논리 아이템 삭제 조건으로 사용하지 마세요.

UI 해상도와 3D 내부 렌더 해상도를 분리해 조절할 수 있어야 합니다.

60fps는 목표이며 검증 결과와 구분하세요.
실제 테스트한 기기, 브라우저, 뷰포트, 품질, 프레임 상태를 기록하세요.
4K나 6인 조건을 확인하지 않았다면 확인했다고 보고하지 마세요.

WebGL 초기화 실패, 컨텍스트 손실, 모델 로딩 실패,
입력 포커스 문제를 구분해 확인 가능한 오류 화면이나 로그를 제공하세요.


12. 구현 순서와 완료 기준

다음 순서로 실행 가능한 상태를 유지하며 구현하세요.

1) 기존 코드·에셋 조사와 충돌 정리
2) 실제 3D 맵·조명·카메라와 캐릭터 이동
3) 고철 집기→가공→실물 출력→직접 설치
4) 두 실제 클라이언트 검증 후 최대 6인 검증
5) Meshy 모델과 캐릭터 동작, 단계별 로켓 외형 적용
6) 실제 상태를 사용하는 HUD와 해상도 대응
7) 컨베이어·크레인·설비 제작과 설치
8) 본편 진행 연결, 밸런스·저장·복구·성능 검증

기본 이동과 집기가 안 되는 상태에서
시각 효과만 계속 추가하지 마세요.

개발용 작은 루프를 본편 전체가 완성된 것처럼 보고하지 마세요.

완료 판정:

- 실제 3D 바닥을 걷고 벽·기계에 막히며 램프를 오른다.
- 고철을 집으면 원래 위치에 복사본이 남지 않는다.
- 내려놓거나 던진 물건을 다시 집을 수 있다.
- 가공 결과가 출력 트레이의 실제 물건으로 나온다.
- 그 물건을 운반해 설치해야 로켓 외형과 준비도가 바뀐다.
- 동시에 같은 물건을 집어도 중복 소유가 발생하지 않는다.
- 1~6인 세션에서 이동·손 상태·가공·설치가 일치한다.
- 출력 정체, 잘못된 투입, 반복 입력, 접속 종료·재접속,
  저장·불러오기로 물건이 사라지거나 복제되지 않는다.
- 컨베이어와 크레인이 같은 실물을 운반하고 막히면 대기한다.
- 모든 HUD 버튼과 조작 안내가 실제 기능과 일치한다.
- 지정 해상도에서 스크롤·겹침·잘림 없이 플레이할 수 있다.
- 기본 카메라에 자동 회전·자동 줌·머리 흔들림·모션 블러가 없다.

검증 결과는 통과·실패·미검증으로 구분하세요.

최종 보고에는 다음을 포함하세요.

- 변경 요약
- 실행 방법
- 실제 게임 화면 캡처
- 가능한 경우 직접 조작한 짧은 영상
- 사용·추가한 모델 목록
- 밸런스 변경표
- 검증 결과와 남은 문제

생성된 컨셉 이미지를 실제 실행 화면의 증거로 제출하지 마세요.

가장 중요한 완료 기준:

게임에 접속한 내가 3D 작업장 안을 직접 걸어 다니며,
보이는 고철 한 개를 집고, 기계에서 실물 부품을 만들고,
그 부품을 발사대까지 가져가 설치할 수 있어야 합니다.
함께 접속한 동료에게도 그 과정이 동일하게 보여야 합니다.
