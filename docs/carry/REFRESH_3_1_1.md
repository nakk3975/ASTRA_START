# 이동 대기열과 초반 설비 — 3.1.1

2026-11-17 KST. 저장 규칙은 quarry-3.1.0 그대로이며 경제·아이템 ID·설비 등급·저장 데이터를 변경하지 않는다.

## 이동 결함과 수정

화면을 그릴 때마다 별도 이동 구간을 만들던 코드에서 높은 주사율과 느린 HTTP 응답이 겹치면, 최대 90개 대기열이 차고 이후 이동 시간이 버려졌다. 360ms 왕복 지연에서 2.4초 이동 시험은 기존 코드의 144/240/360Hz 조건에서 실패했다. 240Hz의 기대 이동량 8.4m 중 약 4.35m만 적용됐다.

전송하지 않은 같은 방향 입력을 최대 50ms 구간으로 합치고, 이미 전송한 구간은 절대로 수정하지 않는다. 화면의 위치 예측은 각 프레임에서 즉시 수행한다. 키업과 방향 전환은 기존 즉시 전송을 유지한다. 서버의 번호 확인·중복 제거·시간 예산도 유지한다.

`tests/movement-refresh.test.ts`의 60/144/240/360Hz + 360ms 왕복 지연 네 조건에서 전체 이동 거리, 정지 후 추가 변위 0, 최종 서버 좌표 일치, 대기열 완전 소진을 확인했다. 별도 시험으로 재전송 구간의 불변성과 방향 전환을 확인한다. 주사율은 계산 시뮬레이션 조건이며 실제 모니터 FPS 측정값이 아니다.

## 초반 설비 외형

종류가 달라도 같은 작은 상자가 올라가던 낡은 설비를 수공구 중심의 6개 외형으로 분리했다. 신규 유료 모델 생성은 없다. 개량 이후의 기존 Meshy 모델은 계속 사용한다.

| 설비 | 낡은 등급의 외형 |
|---|---|
| 작업대 | 널빤지·보강띠·모루·망치 |
| 제련기 | 내화재 가마·화구·굴뚝·풀무 |
| 부품 제작기 | 목재 가대·나사축·손바퀴 프레스 |
| 연료 혼합기 | 금속띠를 두른 통·교반 손잡이·배출구 |
| 조립기 | 회전 받침·조립용 고정구 |
| 설비 제작대 | 공구 걸이·바이스·제작 상자 |

실제 코드로 만든 메시이며 Meshy 생성물로 표시하지 않는다. 각 모델은 236~516삼각형, 3~6개 재질 묶음이다. 지면 접지와 기존 충돌 폭·깊이 안에 드는지 검사했다. 초기 설비도 캐릭터 가림 처리에 포함했다.

`scripts/export-starter-machines.ts`와 `scripts/render-starter-machines.py`로 재현할 수 있다. `evidence/starter-machines-offline.png`는 게임용 메시를 Blender CPU에서 별도 렌더링한 형태 검수 이미지다. 실시간 게임 캡처가 아니다.

## 검증

- 설계 검사·97개 테스트·TypeScript·웹 빌드 통과.
- 실제 6개 WebSocket 연결, 동일 물건 동시 집기, 이동·정지, 접속 종료 회수, PostgreSQL 재시작 복구 통과.
- 로컬 브라우저에서 새 작업장 80코인 → 40코인 작업대 구매 → 손에 상자 표시 확인.
- 사이트 소스 복사본에 빠졌던 기존 DB 마이그레이션을 GitHub의 동일 원본으로 복구해 개발 서버가 시작되도록 했다.
- 원격 브라우저는 WebGL2 생성 실패. 실제 3D 조작·GPU 프레임 속도·사람의 6인 협동 감각은 미검증이다.

기존 게임 주소와 소유자 전용 접근 범위를 유지한다. 기존 작업장은 새로고침으로 적용되며 새로 만들 필요는 없다. 80코인과 빈 공방으로 시작하는 새 성장 흐름을 처음부터 보고 싶을 때만 새 작업장을 만든다.
