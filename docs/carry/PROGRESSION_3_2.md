# 3.2.0 — 설치 정지 수정과 철부터 시작하는 공방

2026-11-17 KST. 저장 규칙 quarry-3.2.0.

## 설치 후 화면 정지

3.1.2의 기본 설비는 이름표 Sprite를 포함한 그룹이다. 가림 처리의 Raycaster에는 camera가 없었고 그룹 전체를 재귀 검사해 Sprite.raycast에서 `Cannot read properties of null (reading 'matrixWorld')`가 발생했다. 다음 프레임도 같은 예외를 반복해 화면이 정지했다.

이름표·UI를 검사 대상에서 제외하고 실제 Mesh만 검사한다. 정사영 카메라에 맞는 평행 광선과 최신 월드 행렬을 사용한다. 화면 갱신 예외는 조용한 정지 대신 저장을 유지하는 오류/3D 재시작 안내로 표시한다.

`scene-installation.test.ts`는 이전 오류를 직접 재현하고 기본 장비 6종의 생성·120프레임 회전·이름표 제외·삭제 이후 가림 검사까지 확인한다. 이 CPU 기반 Three.js 시험은 GPU 렌더/FPS 검증이 아니다.

## 새 시작과 광맥

인원과 무관하게 0코인·낡은 작업대 1대(최하위 등급)·철광석만 시작한다. 철을 직접 캐서 작업대 금색 입력 받침대에 넣고 청록 출력 받침대에서 주괴를 집는다. 주괴/철판을 판매하거나 로켓에 납품해 코인을 모은다. 추가 설비는 기존대로 구매·운반·직접 설치한다.

| 광맥 | 선행 광맥 | 1인 코인 | 필요 XP |
|---|---|---:|---:|
| 철광석 | 처음부터 | 0 | 0 |
| 구리광석 | 철광석 | 20 | 12 |
| 규석 | 구리광석 | 45 | 30 |
| 석탄 | 규석 | 70 | 65 |

코인은 기존 인원별 연구 비용 보정을 적용하고 XP는 조건으로만 사용한다. 광맥 개발에서 해금 비용·선행 조건·현재 자금/XP를 확인한다. 잠긴 광맥은 실제 맵, 충돌 벽, 채굴 대상과 자동 채굴에서 제외하며 관련 레시피도 개방 후 노출한다. 해금 시 작업자나 물건이 새 광맥 위치에 있으면 소비 없이 거부한다.

기존 저장의 자금·물건·장비·이미 열려 있던 광맥은 보존한다. 새 시작 조건은 새 협동 작업장에 적용한다. 기존 저장을 강제 초기화하지 않는다.

## 검증

- 설계 검사, 119개 테스트, TypeScript/Vite 빌드.
- HTTP Worker와 실제 SQLite: 0코인/작업대1대 생성, 유료 해금·동일 명령 재전송, 재접속 시 잠금 상태 유지, 작업대 회수·재설치 후 저장.
- 회귀 시험: 초기 1~6인 조건, 잠긴 광맥 채굴/강화 차단, 철 가공·판매만으로 순차 해금 가능한 경제, 선행조건/자금/XP/중복 소비, 위치 점유 거부, 이전 저장 반복 마이그레이션.
- 1/2/4/6인 목표량 단일 이동 봇: 초기 자금/아이템/위치 주입 없이 전체 발사 성공. 추가 작업대 구매·배치·회수·재배치 포함. 증거 `evidence/progression-3.2-campaign-{1,2,4,6}.json`.
- 실제 6개 WebSocket과 PostgreSQL: 7번째 입장 거부, 물건 경합, 이동·키 해제·행동 순서, 중복 명령 제거, 연결 해제 회수, DB 재시작 후 저장 복구 통과.
- 브라우저 로비 v3.2.0 및 새 시작 안내 확인. QA 브라우저 WebGL2 미지원으로 실제 3D 조작감·FPS·사람의 협동 플레이는 미검증.
