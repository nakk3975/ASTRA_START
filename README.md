# 고철로 우주까지 · Scrap to Orbit

1~6인 협동으로 폐품을 가공하고 자동화 공장을 만들어 여섯 건설 단계와 발사를 진행하는 웹게임입니다. **v1.1 Meshy 3D 전환 작업 중이며, 완성/출시 승인 상태가 아닙니다.**

- 원본 경제·맵 데이터 유지. 기존 버전은 `archive/design-v1.0` 브랜치에 보존했습니다.
- 실제 Meshy 모델은 작업자·가공기·로켓 하부 선체 3개부터 제작합니다. 나머지 23개는 첫 세 모델의 게임 화면 검수 통과 후 제작합니다.
- 현재 QA 브라우저는 WebGL이 비활성화되어 실제 3D 화면 검수가 **BLOCKED**입니다. 미제작 시설은 명시적인 제작 대기 표식으로 표시됩니다.
- 현재 변경분의 검증/미검증 범위는 [v1.1 작업 보고서](docs/qa/V1_1_REPORT.md)를 확인하세요. 이전 스크린샷·보고서는 v1.0 이력이며 새 렌더러의 증거가 아닙니다.

## 첫 세 모델 확인

[비공개 모델 검수 화면](https://scrap-to-orbit-model-review.dsfs3975.chatgpt.site)에서 작업자·가공기·로켓 하부 선체를 확인할 수 있습니다. 전체 게임 서버가 아닌 검수 전용 화면입니다. 세 화면 크기, 두 품질, 작업자 5동작/6명, 시설 방향을 바꿔 확인하고 JSON 기록을 내려받을 수 있습니다.

`npm run build:review`로 같은 검수 화면을 `dist/review/`에 빌드할 수 있습니다.

## 빠른 실행

Node.js **24.22.1 이상, 25 미만**이 필요합니다. Node 버전은 `.nvmrc`, 정확한 npm 의존성은 `package-lock.json`에 고정되어 있습니다.

```bash
git clone https://github.com/nakk3975/ASTRA_START.git
cd ASTRA_START
npm ci
npm run dev
```

브라우저에서 **http://localhost:2567**을 엽니다. 첫 3개 모델 검수 화면은 **http://localhost:2567/asset-review**입니다. 1366×768, 3840×2160, 800×360 CSS 캔버스와 표준/저사양을 선택할 수 있습니다. `DATABASE_URL`을 지정하지 않은 개발 모드에서는 실제 PostgreSQL을 `.local/postgres`에 자동 초기화합니다. 첫 실행 시 PostgreSQL 배포본 설치 시간이 필요할 수 있습니다. 서버를 다시 켜면 같은 DB를 사용합니다.

Windows PowerShell에서도 같은 명령을 사용합니다. 환경 변수를 파일로 관리하려면 `Copy-Item .env.example .env` 후 값을 편집하세요. 자동 PostgreSQL 배포본을 실행할 수 없는 환경에서는 기존 PostgreSQL 또는 아래 Docker 방식을 사용합니다.

```bash
docker compose up -d postgres
```

`.env`에 다음을 설정한 뒤 `npm run dev`를 실행합니다.

```dotenv
DATABASE_URL=postgres://orbit:local-orbit-only@127.0.0.1:55432/orbit
PORT=2567
```

위 암호는 로컬 개발 전용입니다. 운영에는 외부 영구 PostgreSQL과 별도 비밀을 사용합니다.

## 친구와 플레이

1. 닉네임을 입력하고 계획 인원 1~6명의 작업장을 만듭니다.
2. 생성 직후 표시되는 **작업장 ID와 소유자 복구 키**를 보관합니다. 복구 키는 친구에게 보내는 초대 코드와 다릅니다.
3. 상단의 초대 버튼으로 링크를 복사합니다. 친구는 별도의 기기 또는 브라우저 프로필로 입장합니다.
4. 모두 준비를 누른 뒤 진행자가 작업을 시작합니다. 계획 인원에 따른 로켓 건설량은 이때 고정됩니다.
5. 소유자도 일반 플레이어처럼 작업하며, 개인 가방과 수동 작업대 채널은 다른 사람에게 공개되지 않습니다.

동일 브라우저 프로필의 여러 탭은 같은 게스트입니다. 새 탭이 기존 탭의 제어권을 교체하므로, 6인 시험에는 6개의 독립된 게스트 세션을 사용해야 합니다. 인터넷 협동에는 외부에서 접근 가능한 HTTPS 웹서비스와 WebSocket 프록시가 필요합니다. 이 저장소를 GitHub에 올리는 것만으로 게임 서버가 배포되지는 않습니다.

## 조작과 진행

| 조작 | 동작 |
|---|---|
| WASD / 방향키 | 캐릭터 직접 이동 |
| E | 가까운 대상과 상호작용 / 채집 유지 |
| 마우스로 시설 선택 | 상태 열람 및 작업 패널 |
| B / R | 건설 열기 / 배치 회전 |
| F / 마우스 휠 | 캐릭터 카메라로 복귀 / 확대·축소 |
| 1~4 | 가방 슬롯 선택 |
| 모바일 가로 | 가상 조이스틱과 작업 버튼, 패널 버튼 |
| 모바일 세로 | 입력 중지와 회전 안내, 상태 열람 |

폐품 구역의 밝은 작업 지점에서 채집합니다. 수동 작업대에 재료를 투입하고 제조법을 선택한 후 제작합니다. 완성품을 출력에서 가방으로 수거해 로켓 앞에 납품합니다. 단계 자재를 모두 채운 뒤 실제 조립 작업을 완료해야 다음 단계가 열립니다.

- **M1 이후:** 자동 가공기, 부품 제작기, 태양광을 설치할 수 있습니다.
- **M2 이후:** 배송 허브와 품목별 링크로 운반을 자동화합니다. 출발 자원은 실제 화물로 이동하며 도착 공간을 예약합니다.
- **M3 이후:** 지정 패드의 자동 수거기, 추진 팩 합성기, 모듈 조립기 등을 사용합니다.
- **M6 조립 후:** 3가지 점검을 수행하고 현재 접속자 전원이 발사에 동의합니다. 카운트다운 중 취소나 이탈은 발사를 취소하며 추가 연료를 차감하지 않습니다.

자동 설비도 처음부터 무료 지급되지 않습니다. 비용은 작업자의 가방에서만 지불합니다. 창고·작업대·기계 간 원격 순간이동은 허용하지 않습니다. 인벤토리가 포화되면 창고 앞의 ‘공용으로 임시 보관’을 사용할 수 있습니다. 철거는 재고와 비행 화물을 정리한 후 가능하며 실제 지불 비용은 현장 상자로 반환됩니다.

## 포함된 구현

- 서버 권위의 20Hz 이동·상호작용과 최대 6개 접속/개인 제작 채널
- 4슬롯 가방, 공용 창고, 현장 회수상자, 전달·수거·포화 대기
- 원본 10개 제조법, M1~M6 조립, 전력 비례 생산, 설치·이동·강화·철거
- 자동 가공, 실제 `cargo` 객체와 비행 시간, 출발·도착 용량 예약, 두 단계 공정 배송 분배, 자동 수거
- 게스트 인증, 일회용 입장 티켓, 소유자/진행자 분리, 소유권 합의 이전과 복구 키 교체
- PostgreSQL 변경 기록·스냅샷·멱등 영수증, writer lease/epoch 차단, COMMIT 이후 ACK
- 재접속, 같은 게스트 제어권 교체, 무접속 시 시간 정지, 수동 일시정지 유지
- 발사 준비 투표·점검·취소·결과 보존
- React UI, 실제 Meshy GLB를 사용하는 Three.js 월드, WebGL 불가 시 오류 안내와 재시도 화면 (2D를 3D 검수 대체물로 사용하지 않음)
- 한국어 안내, 가로 터치 조작, 그래픽 품질 전환, 음향 토글, 단계 도움말

## 실행한 시험과 남은 검수

상세 결과는 [QA 보고서](docs/qa/REPORT.md), v1.1 원본 160행에 대응하는 결과는 [acceptance_tests.csv](docs/qa/acceptance_tests.csv)에 있습니다.

```bash
npm run check       # 원본 설계 검산 + 코어 시험 + TypeScript + 웹 빌드
npm run test:full   # 코어 1인/6인 완주 시뮬레이션. 실제 시간/브라우저 시험 아님
npm run test:shutdown # 개발 서버를 끈 뒤 실행. 실제 로컬 PostgreSQL 정상 종료 시험
```

개발 DB에서 `.env`에 `ORBIT_QA=1`을 설정하고 서버를 시작하면 실제 HTTP/WS/DB 통합 시험을 수행합니다. 독립된 시험 게스트와 방을 만들고 결과를 `docs/qa/evidence/live-integration.json`에 씁니다. 경합 시험은 명시적인 테스트 재고/단계 fixture를 사용하며 완주 증거와 분리됩니다. **운영 모드에서는 이 시험을 실행하지 않습니다.** 시험 후에는 `ORBIT_QA` 설정을 제거하세요.

`.env`에 `ORBIT_FULL_QA=1`을 설정하고 개발 서버를 시작하면 실제 HTTP·WebSocket·PostgreSQL을 거쳐 빈 방부터 발사까지 진행하는 온라인 시험 봇을 실행합니다. 이 시험은 방의 시뮬레이션 시계만 가속하며, 50ms tick·최대 5tick 커밋·DB 저장 경로는 유지합니다. 입력 만료와 요청 제한은 가속된 논리 시계를 기준으로 동작하며, 소켓 심박과 writer lease는 실제 벽시계를 사용합니다. 자원/좌표 주입이나 운영용 치트 API는 없습니다. `ORBIT_FULL_QA_PLAYERS=6`은 6인 시험만 선택합니다. 결과는 `docs/qa/evidence/network-full-runs.json`에 기록됩니다. 정상 속도 브라우저 완주와 구분하며, 시험 뒤 두 설정을 제거하세요.

`npm run test:full`은 자원 지급과 좌표 순간이동 없이 이동 입력, 채집, 제작, 유료 설비 설치, 물류, 자동 수거, 점검, 투표를 진행합니다. 6인 모형은 작업자를 순차로 배정하는 보수적 시험 봇이므로 실제 협동 시간이나 밸런스 목표를 입증하지 않습니다. 원본 경제 수치는 변경하지 않았습니다.

아직 확인하지 않은 핵심 항목은 정상 시간 1인/6인 온라인 완주, 모바일 터치만으로 전체 완주, GPU가 있는 브라우저의 Three.js 화면, 프로세스 강제 종료/네트워크 분리/COMMIT 응답 유실 조합, 3개 방 동시 부하 및 저사양 FPS입니다. 미실행 시나리오를 PASS로 기입하지 않았습니다.

## 배포

운영 필수 환경 변수는 `NODE_ENV=production`, `DATABASE_URL`, `PUBLIC_ORIGIN`, `SESSION_SECRET`입니다. `PUBLIC_ORIGIN`은 실제 HTTPS 원점과 정확히 일치해야 합니다. `PORT`는 배포 서비스가 지정할 수 있습니다.

```bash
npm ci
npm run build
npm start
```

`render.yaml`과 `Dockerfile`은 배포 준비 파일입니다. **외부 서비스 생성이나 실제 배포는 수행하지 않았습니다.** `render.yaml`은 기존 외부 PostgreSQL 주소를 입력받으며 유료 DB를 자동 생성하지 않습니다. 처음에는 Node 인스턴스 1개로 운영하세요. 방별 writer lease가 있어도 여러 웹 인스턴스로 분산하는 라우팅/공유 matchmaking은 이 버전에 포함하지 않았습니다.

설정, 백업, 오류 복구, 저장 확정 규칙은 [운영 문서](docs/OPERATIONS.md)를 참고하세요.

## 저장소 구조와 설계 기준

| 경로 | 역할 |
|---|---|
| `design/` | 첨부 원본 전체. README_FIRST, ASTRA_START_PROMPT, 상세 Markdown, JSON, 미실행 원본 CSV |
| `packages/content/` | 원본 JSON 직접 로드, 버전·수치·목표 계산 |
| `packages/game-core/` | 이동·경제·공장·물류·조립·발사 순수 로직과 보존 불변식 |
| `packages/protocol/` | strict 명령 스키마, 입력 검증, 변경분 형식 |
| `apps/server/` | Colyseus room, 단일 writer actor, HTTP 인증, PostgreSQL repository |
| `apps/web/` | React UI, Three.js/Canvas 렌더러, 재접속·명령 결과 확인 |
| `migrations/` | PostgreSQL 최초 스키마 |
| `tests/` | 코어 규칙, 경제 완주, 실제 소켓·DB 통합 시험 |
| `docs/qa/` | 99행 결과표, 보고서, 실행 증거와 실제 화면 |

경제는 `design/balance_v1.json`, 지도는 `design/map_v1.json`, 입력·네트워크·운영 한도는 `design/runtime_v1.json`이 기준입니다. [추적표](docs/TRACEABILITY.md)와 [충돌 기록](docs/conflict_log.md)에 구현 대응과 문서 차이를 기록했습니다. [자산·라이선스](docs/ASSET_LICENSES.md)도 확인할 수 있습니다.
