# 고철로 우주까지 설계 패키지 사용 안내

이 패키지는 **1~6인 온라인 협동 웹게임 고철로 우주까지**를 ASTRA가 구현할 때 사용할 기획서, 실행 데이터, 계산 근거와 인수 검증 목록이다. 폐품을 직접 수집하고 가공·운반·건설한 뒤 생산과 배송을 자동화하여 로켓을 완성하고 발사하는 전체 흐름을 다룬다.

설계 버전은 **1.0.0**, 기준일은 **2026년 11월 16일**이다. 경제 및 콘텐츠 데이터의 정확한 버전 식별자는 각 JSON에 기록되어 있다. 현재 작성된 것은 설계와 계산 도구이며, 실제 게임 클라이언트와 서버는 앞으로 구현해야 한다.

## 1 ASTRA에게 전달하는 방법

1. 이 패키지의 **전체 ZIP**을 ASTRA 대화 또는 개발 작업 공간에 전달한다.
2. ASTRA가 압축을 풀어 모든 파일을 읽을 수 있게 한다. 구현 작업 공간에 이미 있는 사용자 코드와 설정은 보존한다.
3. **ASTRA_START_PROMPT.md의 전체 내용**을 작업 지시문으로 전달한다.
4. 아래 순서대로 문서와 데이터를 읽고 설계 검증을 실행한 후, 상세 기획서의 P0부터 P6까지 구현한다.

PDF는 사람이 구조와 표를 검토하기 위한 문서다. ASTRA에는 Markdown 원문, JSON, CSV와 검증 스크립트가 함께 있어야 수치와 상태 규칙을 정확히 확인할 수 있다. 실제 저장소 쓰기나 배포는 해당 작업 대화에서 사용자가 부여한 권한을 따른다.

| 순서 | 파일 | 읽는 목적 |

## 3 원본 데이터와 문서의 역할

| 구분 | 기준 원본 | 적용 원칙 |
| --- | --- | --- |
| 게임 규칙과 예외 | 상세 Markdown 기획서 | 상태 전이, 자원 처리, 협동, 저장과 실패 복구의 동작을 따른다. |
| 경제 실행 수치 | balance_v1.json | 가격, 제조법, 수율, 작업 시간, 목표 수량과 배율을 코드의 별도 숫자로 중복 정의하지 않는다. |
| 지도 실행 수치 | map_v1.json | 좌표, footprint, 접근점, 시작 배치와 후반 배치 예시를 구분하여 읽는다. |
| 공통 런타임 설정 | runtime_v1.json | 입력과 네트워크 등 공통 상수의 원본으로 사용한다. |
| 구현 완료 판정 | acceptance_tests.csv | 실제로 수행한 검증에 증거와 결과를 기록한다. |
| 계산 근거 | 각 분석 JSON과 검증 보고서 | 원본 데이터에서 도출한 결과다. 실행 수치를 이 보고서에서 역으로 복사해 별도 원본으로 만들지 않는다. |
| 가독용 표현 | PDF와 지도 그림 | 원문과 데이터의 내용을 검토하는 용도다. |

세 종류의 JSON은 **경제, 지도, 런타임이라는 각 담당 범위의 단일 원본**이다. 같은 상수를 여러 파일이나 UI 컴포넌트에서 독립적으로 수정하지 않는다. 내용에 충돌이 있으면 위치와 영향을 기록하고 해소한 뒤 구현한다.

경제 수치를 변경하면 데이터 버전, 관련 계산, 문서 표와 테스트 기대값을 함께 갱신한다. 진행 중인 저장 방에는 고정된 콘텐츠 버전을 계속 적용하거나 검증된 마이그레이션을 제공한다. 재계산 도구만 실행하면 Markdown 본문과 PDF까지 자동으로 새로 만들어지는 것은 아니므로 문서의 일치도 함께 확인한다.

## 4 구현 범위에서 먼저 기억할 사항

- 최대 플레이어는 **6명**이다. 계획 인원은 로비에서 1~6명으로 설정하고 게임 시작 시 고정한다.
- 계획 인원은 **로켓 건설 목표 수량**에만 적용한다. 접속 인원이 변해도 이미 시작한 방의 비용을 다시 계산하지 않는다.
- 개인 인벤토리의 **4슬롯**은 인원 제한과 관계없는 별도 규칙이다.
- 캐릭터가 직접 이동하고 채집·가공·운반·납품·조립하는 플레이가 필수다.
- 자동 가공, 실제 비행 중 화물을 가진 배송 링크, 자동 수거기는 모두 1.0에 포함된다.
- 혼자 모든 필수 단계를 완료할 수 있어야 한다. 2명 이상이 동시에 조작해야만 진행되는 조건을 추가하지 않는다.
- 저장과 재접속, 실제 6개 연결의 협동, 여섯 건설 단계와 발사 결과까지 구현해야 한다.
- 세로 모바일은 기존 플레이어 자리 하나를 유지하는 읽기 전용 상태 보기다. 직접 조작은 가로 화면에서 제공한다.
- 지도에 들어 있는 **후반 공장 25대와 자동 수거기 9대 예시를 새 게임 시작 시 지급하지 않는다.** 새 게임은 명시된 시작 설비와 초기 상태만 생성한다.
- 참조 공장의 배송 링크 32개는 비용 계산 예시다. 그 개수로 모든 생산 경로가 완성된다는 증명은 아니다.

## 5 현재 검증된 것과 앞으로 검증할 것

| 구분 | 현재 결과 | 확인한 범위 | 앞으로 확인할 범위 |
| --- | --- | --- | --- |
| 경제 정적 검사 | **21개 검사 그룹 PASS** | 레시피 의존성, 목표 도달성, 비용과 수량, 인원 배율, 전력, 운송 한도와 경계 산식 | 실제 코드의 자원 처리와 저장 무결성 |
| 제조 사건 실험 | **18개 조건 완료** | 1~6인 참조 공장에 공유 중간재 용량 무제한·200·20을 적용한 제조 순서, 목표 충족과 재고 보존 | 실제 해금·투자·채집·걷기·배송·조립을 포함한 전체 플레이 |
| 지도 정적 검사 | **446개 검사 PASS** | 경계, 고체 겹침, 보호 통로, 타일 BFS, 설비 수, 일부 자원 필터와 배송 거리 | 캐릭터 반경 충돌, 카메라 가림, 화면 조작과 성능 |
| 실제 게임 인수 검증 | **99개 모두 NOT_RUN** | 구현 후 확인할 시나리오와 기대 동작을 정의함 | 게임 구현 후 각 항목을 실제 실행 |

제조 사건 실험은 필요한 원료·제조법·참조 설비가 처음부터 있다고 가정하는 제한된 계산 모형이다. 실제 게임을 18번 완주한 기록이 아니다. 지도 검사도 실제 브라우저 6개를 연결한 시험이 아니다.

**플레이시간은 목표 범위다.** 계산한 제조 시간이나 공정 용량의 하한을 실제 완주시간으로 표시하지 않는다. 조작의 재미, 처음 하는 사용자의 이해도, 네트워크 지연, DB 장애 복구, 장치별 FPS와 1인·6인 실제 완주는 구현 후 측정한다.

**acceptance_tests.csv**에는 UX 48개, 서버 30개, 교차 규칙 21개가 있다. 배포된 패키지의 모든 행은 **status=NOT_RUN**이며 증거 칸은 비어 있다. ASTRA는 검증을 실제 수행한 뒤에만 상태를 바꾸고 실행 환경, 명령 또는 재현 절차와 결과를 기록한다.

## 6 설계 계산을 다시 실행하는 방법

**Python 3.10 이상**이 필요하다. 검증은 Python 표준 라이브러리만 사용하며 추가 패키지 설치가 필요 없다. ZIP의 모든 파일을 같은 폴더 구조로 풀고, 이 README가 있는 폴더에서 실행한다.

일반적인 실행 명령:

~~~text
python verify_design.py
~~~

Windows에서 Python Launcher를 사용하는 경우:

~~~text
py -3 verify_design.py
~~~

macOS 또는 Linux에서 Python 명령이 python3인 경우:

~~~text
python3 verify_design.py
~~~

이 스크립트는 다음 작업을 순서대로 실행한다.

| 실행 파일 | 수행 내용 | 주요 결과 파일 |
| --- | --- | --- |
| validate_balance.py | 경제 데이터 정적 검사 | validation_results.json |
| analyze_balance.py | 원료 BOM, 투자비, 생산 용량과 전력 계산 | balance_analysis.json |
| simulate_factory_schedule.py | 18개 제조 사건 조건 계산 | factory_schedule_analysis.json |
| analyze_automation.py | 자동 원료 공급과 수거기 MK2 효과 계산 | extractor_mk2_analysis.json |
| validate_map_v1.py | 지도 배치와 접근성, 일부 배송 거리 검사 | map_validation.json, map_validation.md |

정상 종료 시 마지막에 **DESIGN CHECKS PASSED**가 포함된 메시지가 나온다. 이는 위 설계 계산의 통과를 뜻한다. 게임 서버 실행, DB 연결, 멀티플레이 또는 브라우저 플레이를 수행하는 명령이 아니다.

실행은 계산 결과 JSON과 지도 검증 요약을 다시 생성한다. 실패하면 첫 실패의 원인과 변경한 입력 데이터를 확인한다. 의도적인 밸런스 변경으로 기존 기대값이 달라졌다면 독립 검산, 버전 갱신, 문서와 검증 기대값의 정합을 함께 처리한다. 실패 항목을 삭제해 통과로 만드는 방식으로 처리하지 않는다.

## 7 구현 이후 남겨야 하는 결과

ASTRA는 상세 기획서의 단계별 완료 기준에 따라 실행 가능한 코드를 제공하고, 다음 증거를 분리하여 남긴다.

1. 순수 게임 코어의 자동 검증.
2. 실제 PostgreSQL을 사용하는 저장·복구·멱등성 검증.
3. 실제 별도 연결 6개를 사용하는 동시 작업 검증.
4. 1366×768, 3840×2160, 모바일 가로 800×360과 세로 상태 전환의 화면·조작 검증.
5. 1인과 6인의 시작부터 발사까지 실제 완주 및 관측 시간.
6. 인수 검증 CSV의 결과와 증거, 미해결 결함, 재현 가능한 실행 절차.

최종 전달에는 소스, 환경변수 예시, DB 마이그레이션, 자산 출처, 검증 결과와 실제 확인한 실행 방법을 포함한다. 기획 데이터 검사, 가상 응답 시험, 실제 게임 시험을 서로 구분하여 보고한다.
