# 고철로 우주까지 1.1 — Meshy 3D 설계 패키지

**1~6인 온라인 협동 웹게임**을 ASTRA가 구현하기 위한 전체 설계다. 폐품 수집, 직접 가공과 운반, 자동 생산과 배송, 여섯 단계 로켓 건설과 발사를 다룬다. 이번 개정은 **Meshy의 실제 3D 모델과 고정 방향 정사영 카메라**를 채택한다. 작은 디오라마를 내려다보는 느낌으로 만들고 화면 회전·흔들림·모션 블러·자동 줌은 넣지 않는다.

설계 **1.1.0**, 기준일 **2026년 11월 16일**. 경제 콘텐츠 1.0.0-design과 지도 1.0.0은 유지한다. 런타임·표현·자산 계획은 1.1.0-design, 통신 프로토콜은 2다. **실제 게임과 Meshy 모델은 아직 제작하지 않았다.** NOT_GENERATED와 NOT_RUN을 실제 제작·검증 완료로 읽지 않는다.

## 1. ASTRA에게 전달하는 방법

1. **Scrap_to_Orbit_Meshy_ASTRA_Package_v1.1.zip 전체**를 작업 대화 또는 개발 작업 공간에 전달한다.
2. ASTRA가 압축 안의 모든 파일을 읽을 수 있게 한다.
3. **ASTRA_START_PROMPT.md 전체 내용**을 구현 지시문으로 전달한다.
4. 전체 기획서와 다섯 종류의 설정 데이터를 읽고 `python verify_design.py`를 실행한 뒤 P0부터 P6까지 구현한다.

PDF는 사람이 검토하는 문서다. ASTRA에는 Markdown, JSON, CSV와 검산 스크립트를 함께 전달한다. 기존 저장소의 사용자 코드와 설정은 보존한다.

## 3. 데이터 권한과 변경

경제는 balance_v1.json, 지도는 map_v1.json, 공통 실행 제한은 runtime_v1.json, 카메라·품질은 presentation_v1_1.json, 자산 규격은 asset_catalog_v1_1.json이 담당한다. 같은 수치를 UI와 서버에서 독립 하드코딩하지 않는다. 카탈로그의 전체 삼각형·draw call 예산은 표현 설정을 검산하는 사본이며 서로 다르면 검산이 실패해야 한다.

상태 전이·예외는 상세 Markdown을 따른다. 충돌이 있으면 위치와 영향을 기록하고 해결한다. PDF와 지도 그림은 가독용 표현이다. 모델·LOD·가림·품질 변경으로 목표량, 생산 시간, 충돌, 배송 도착 tick을 바꾸지 않는다. 시각 버전은 경제 버전과 구분한다. 출시 manifest는 승인 파일과 해시가 생긴 뒤 만든다.

## 4. 이번 개정의 필수 사항

- 정사영, 고도각 55도, 남동쪽 45도 방향 고정. 기존 XZ 이동과 서버 충돌 유지.
- 화면 중앙 폭 30%·높이 28%는 카메라 정지 영역. 바깥에서만 따라가며 자동 추적 끄기·수동 이동·내 위치 보기 제공.
- 패널은 canvas 위에 겹친다. 열고 닫아도 시야를 바꾸지 않으며 패널 위 휠은 패널만 스크롤한다.
- PC spanHeight 18/22/28, 작은 가로 화면 10/12/15. 자유 회전·핀치·자동 줌 없음.
- 로켓 가림은 로컬 윤곽과 해당 개체 반투명화로 처리. 자동 줌아웃 없음.
- 작업자 1·시작 설비 4·건설 설비 7·운반 및 회수 2·원료 4·로켓 8, 총 26종.
- 첫 제작은 작업자·가공기·로켓 하부 선체 3종. 게임 카메라에서 검수한 뒤 나머지에 같은 스타일 적용.
- 게임 정면 -Z, Meshy 리깅 입력 +Z, 설치 yaw는 `-quarterTurns * Math.PI / 2`. import 보정은 한 번만 적용.
- 실제 작업자 리그와 다섯 동작 필요. 회색 도형·정적인 슬라이딩 캐릭터는 개발 중 대체물.
- 모듈 로켓의 발사대·갠트리는 지상에 남고 FlightRoot만 상승. 카메라는 추적하지 않음.
- Meshy는 개발 중 제작 도구. 플레이 중 생성 API 호출과 브라우저 API key 없음.

## 5. 유지하는 게임 규칙

최대 참가자 6명, plannedPlayers는 로비에서 1~6으로 정하고 시작 후 고정한다. 건설 목표 수량에만 배율을 적용하며 접속·이탈로 재계산하지 않는다. 개인 인벤토리 4슬롯은 인원 제한과 다른 규칙이다.

직접 이동·채집·무전력 수동 가공·운반·납품·조립, 자동 생산·실제 화물 배송·자동 수거, 여섯 단계와 발사, 저장·재접속을 모두 구현한다. 1인도 필수 단계를 완주할 수 있어야 한다.

모바일 가로는 직접 조작, 세로는 이미 참가한 자리 하나를 유지하는 읽기 전용 상태 보기다. 후반 공장 25대와 수거기 9대 예시를 새 방에 무료 지급하지 않는다. 참조 링크 32개는 투자 계산 예시이며 모든 공정 연결의 증명값이 아니다.

## 6. 검증 상태

| 영역 | 현재 확인한 범위 | 확인하지 않은 범위 |
| --- | --- | --- |
| 경제 | 21개 정적 검사 그룹 PASS | 실제 코드·DB 무결성 |
| 제조 | 18개 제한된 제조 사건 모형 완료 | 실제 해금·채집·운반·배송·조립 포함 완주 |
| 지도 | 446개 정적 검사 PASS | 실제 반경 충돌·6인 조작·가림 |
| 3D 표현 | 별도 JSON의 투영·입력·예산·버전 정합 계산 | 실제 GLB·FPS·시각적 편안함 |
| 게임 인수 | 160개 정의, 전부 NOT_RUN | 구현 후 실제 실행 |
| 자산 검수 | 26종 정의, 전부 NOT_RUN | 실제 파일·해시·크기·리그·동작 검사 |

160개는 UX 48, SERVER 30, CROSS_RULE 21, CAMERA 17, VISUAL_INTEGRATION 28, ASSET 16이다. 카메라 단독 시험과 통합 시험은 일부 같은 현상을 다른 경계에서 확인한다. 증거 칸은 실제 실행 후에만 채운다.

제조 모형은 원료·제조법·참조 설비가 처음부터 있다고 가정한다. 게임을 18번 완주한 기록이 아니다. 화면 투영과 삼각형 합계도 실제 가독성이나 FPS를 보장하지 않는다. 목표 플레이시간은 실제 1인·6인 플레이 후 측정한다.

## 7. 검산 재현

Python 3.10 이상, 추가 패키지 없이 실행한다. ZIP을 같은 폴더 구조로 풀고 README 폴더에서 실행한다.

```text
python verify_design.py
```

Windows Launcher는 `py -3 verify_design.py`, python3 환경은 `python3 verify_design.py`를 사용한다.

| 스크립트 | 주요 출력 |
| --- | --- |
| validate_balance.py | validation_results.json |
| analyze_balance.py | balance_analysis.json |
| simulate_factory_schedule.py | factory_schedule_analysis.json |
| analyze_automation.py | extractor_mk2_analysis.json |
| validate_map_v1.py | map_validation.json, map_validation.md |
| validate_presentation.py | presentation_validation.json |

DESIGN CHECKS PASSED는 위 설계 계산의 통과다. 게임 서버·DB·브라우저를 실행하는 명령이 아니다. 검산 실행은 원문과 PDF를 자동 갱신하지 않는다. 변경 시 데이터·문서·계산·버전 정합을 함께 확인한다.

## 8. 구현 후 증거

순수 코어, 실제 PostgreSQL, 실제 별도 연결 6개, 1366×768·3840×2160·800×360과 세로 상태를 구분하여 검증한다. 실제 1인·6인 시작부터 발사까지 완주 시간을 남긴다. Meshy 자산의 출처·사용 조건·해시·폴리곤·텍스처·동작, 최대 장면 프레임 성능과 카메라 체감 결과를 제공한다.

소스, 실행 절차, 환경변수 예시, DB 마이그레이션, 버전, 자산 이력, 검사 결과, 남은 결함을 전달한다. 실제 수행하지 않은 항목은 NOT_RUN 또는 BLOCKED와 이유로 남긴다.
